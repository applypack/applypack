# §7 — Strengthen privacy messaging

**Verdict: the words are there; the claim is not literally true until the dashboard stops loading Tailwind and Inter from third-party CDNs. Adopt the code fix (P2), not the copy.**

## What the plan proposes

A visual *Your resume → your machine → your Postgres — Not our cloud*, with the
supporting points (no account, no subscription, no telemetry, local Docker,
your AI provider, local models), visible before the install instructions.

## What the repo has today

- Landing: hero trust list (*Runs locally or in Docker · Your data stays in
  your Postgres*), `#how` (*Your Postgres — on your machine, nothing leaves
  it*), `#open` (*no accounts, no subscription, no telemetry, no ads*).
- README: *"Everything runs on your machine: your resume, your profile and
  every AI report stay in your own Postgres"*, *"no accounts, no telemetry"*.
- **But** `src/web/layout.tsx:209–215` loads
  `https://cdn.tailwindcss.com` (the Play CDN, compiled in the browser on
  every page) and `https://fonts.googleapis.com/css2?family=Inter…` on every
  dashboard page. Confirmed on the running instance: `curl /jobs` shows the
  four external references. PRODUCT.md records "Tailwind Play CDN" as a
  design constraint.

## Assessment

Adding a "Not our cloud" graphic would repeat three sentences already on the
page. The gap is in the product: every dashboard page load sends the user's IP
and user agent to two third parties, and an install without internet (a VPS
behind a firewall, a laptop on a plane) renders unstyled. Tailwind's own docs
say the Play CDN is not for production. This is the one privacy item worth
the work, and it is a code item, filed in the audit report as finding
**PRIV-1**.

## Steps → TASKS §20, block `dashboard-self-contained`

1. Build the Tailwind CSS once with the CLI over `src/web/**/*.{tsx,ts,mjs}`
   using the theme in `layout.tsx:TAILWIND_CONFIG`; commit the output as
   `src/web/public/tailwind.css` (no runtime build step — CLAUDE.md's rule
   holds). Ninety-two template-literal `class=` sites exist; a test renders
   every page and asserts each class token in the HTML is in the CSS, which is
   how a constructed name (`bg-${tone}`) gets caught.
2. Self-host Inter: `site/public/fonts/inter-latin.woff2` + its licence are
   already in the repo; copy under `src/web/public/fonts/`.
3. Remove the two preconnects and the CDN script; a unit test greps
   `layout.tsx` for `cdn.tailwindcss.com` / `fonts.googleapis.com` and fails
   if they return.
4. PRODUCT.md and DESIGN.md: replace the "Tailwind Play CDN" constraint with
   "a committed Tailwind build, regenerated by `npm run css` when a class is
   added". README's "nothing leaves your machine" then needs no asterisk.
