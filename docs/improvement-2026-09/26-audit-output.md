# §26 — What the audit should produce

**Verdict: adopt the shape, keep the repo's naming.**

The plan asks for `docs/audits/full-project-audit-2026-09.md` with twenty
sections. The repo already has one audit file in its own naming —
`docs/audit-2026-09.md` (the post-§14 pass) — and CLAUDE.md links there. The
new pass is [docs/audit-2026-09-10.md](../audit-2026-09-10.md) with the
plan's sections folded to what has content: environment and commands, the
coverage map (verified / partial / not verified, with the reason), findings
by area with severity and evidence, what was checked and is clean (with the
command, so the next pass starts elsewhere), needs-maintainer-review, the
fix order, what was not tested.

Issues are not created from an analysis session (plan rule 6 and 7 agree:
evidence first, duplicates searched); the report lists the candidates and
the existing issues they map to, and TASKS §20 carries the work.
